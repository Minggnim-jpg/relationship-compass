# 多对象独立档案

## 数据位置与结构

用户指定的数据目录优先；否则采用当前用户工作目录下的 `compass-data/`。首次建档时告知实际绝对路径。不得把真实记录写进 Skill 安装目录、共享源或公开示例。若当前目录就在 Skill 源内，先询问保存位置。

```text
compass-data/
├── index.json
└── people/
    ├── p-<uuid>/
    │   ├── profile.md
    │   ├── config.md
    │   ├── timeline.md
    │   ├── compass.md
    │   └── sessions/
    └── p-<另一个uuid>/...
```

`index.json` 只保存版本与对象映射，例如 `{"version":1,"people":[{"id":"p-<uuid>","label":"小 A","aliases":[]}]}`。索引不包含关系细节、评分或聊天原文。ID 由 UUID 生成，昵称不直接拼入路径；改昵称不改 ID。同名或别名匹配多个对象时必须澄清，不能自行合并。

## 对象选择与隔离

1. 先从用户本次指定的名字或 ID 匹配索引。新会话未指定对象时询问；当前对话已唯一确定对象且未出现切换或歧义时可以沿用，不使用跨会话全局 active_person。
2. 找不到对象时，只有用户已要求建档或记录才建立新对象。对象身份不明确时先确认。纯分析可继续基于本次提供的材料，但不能猜测档案归属。
3. 只读取索引和所选对象目录下所需文件。不要全量扫描 people/，不要在分析 A 时读 B 的记录。用户提供多对象材料时先标明每段归属，不能把整段对话复制到所有档案。
4. 仅在用户明确要求跨对象比较时读取指定对象；输出保持来源标识，不把比较内容写入单个对象的事实记录。
5. 读写前检查解析后的路径仍在所选数据根目录和对象目录内；不通过符号链接读写到其他对象或目录。这里是文件组织及 Agent 读取规则的逻辑隔离，不是加密或操作系统权限隔离。

## 建档与真实留存

用户要求建立对象档案时，创建唯一 ID、对象目录、背景文件与空时间线、未知状态的罗盘，再更新索引。只填用户提供的信息；昵称可以是化名。用户偏好保存于对应对象 config.md。

用户要求记录一次互动时：

1. 核对对象；提取事件日期与来源。日期不明就标记未提供，不把保存日期冒充事件日期。
2. 新建 `sessions/<保存时间>-<uuid>.md`，避免同日覆盖。记录如下字段：
   - 对象 ID、事件日期、记录时间。
   - 用户提供的事实：区分原文和摘要，附来源类型及可用的来源标识。不把用户叙述称为已独立核实。
   - 用户的感受、期待与边界。
   - AI 分析：可能解释、依据、缺失信息，明确为推测。
   - 建议：尚未执行；只有用户反馈已执行时才更新状态。
   - 后续结果：未反馈 / 用户反馈的实际结果，关联原事件。
3. 给 timeline.md 追加事件摘要及 session 相对链接；根据该对象已有证据更新 compass.md。不得用其他对象的数据补齐未知项。
4. 写入前重读目标文件，保留已有记录；避免并发覆盖，无法安全合并时停止该写入并说明。纠错时标注更正及对应事件，不能悄悄改写历史。
5. 写完读回，确认对象 ID、内容与路径一致，给用户实际文件路径和保存摘要。部分写入失败时明确哪些已保存、哪些未保存，不声称全部成功，也不重复追加已存在事件。

用户可以要求查看、修改或删除指定对象资料；删除范围不清时先确认，不能连带其他对象。用户未要求记录时不写文件。宿主没有文件工具或权限时明确未保存，不以聊天记忆代替持久化。

## 历史单对象格式

已有根目录下 profile.md、timeline.md、compass.md 或 sessions/ 时，将其视为未归属旧档案。不得自动归给第一个新对象，也不批量读取其中内容。用户明确指定旧档案对应对象并要求迁移后，复制到该对象目录、校验内容、读回确认；保留原件，除非用户另行要求清理。

## 发布边界

真实数据根目录不纳入开源包。示例必须是明确标记的虚构材料；数据是否发送给模型取决于宿主和模型服务，不能因文件在本地就宣称完全离线或不上传。
